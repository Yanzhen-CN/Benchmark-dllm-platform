# Benchmark-dllm Platform 架构

## 目标

这个目录先作为 Benchmark-dllm 的独立调试平台。它提供配置浏览、任务提交、运行状态和结果展示，但不复制评测、打分和可视化实现。调试稳定后，再决定是否合并到主项目。

## 旧项目带来的经验

旧的 AI-pharmacy 平台验证了三点：

1. 模型、数据集和结果分析适合平行组织。
2. 组件应通过 YAML 注册，界面不硬编码模型列表。
3. 统一入口和历史结果浏览能降低使用成本。

旧项目也把 Conda 环境、依赖安装、文件上传、模型执行和结果分析集中到了 Streamlit 层。这样会让基础环境变重，并使前端承担过多系统职责。新平台保留结构经验，不沿用这部分实现。

## 当前分层

```text
Streamlit pages
    -> platform_core（目录、命令、进程、结果适配）
        -> Benchmark-dllm/run_bench.py
            -> venv_scripts/<model>.py
                -> 各模型独立 .venvs/<model>
```

### 平台层

- 读取 `configs/models`、`configs/datasets` 和 `configs/experiments`。
- 生成可检查的 Benchmark 命令。
- 后台启动任务并保存日志。
- 读取现有输出，不重新计算分数和图表。

### Benchmark 层

- 定义模型与数据集配置。
- 负责生成、打分、可视化和 profiling。
- 维护模型自己的环境启动脚本。

### 模型环境层

- 每个模型使用独立虚拟环境。
- 平台环境只安装 Streamlit 和 YAML 解析依赖。
- 环境创建和更新由现有 `venv_scripts` 完成，页面只显示状态。

## 扩展方式

新增模型时，在 Benchmark-dllm 中加入模型配置和对应启动脚本；新增数据集时加入数据集配置及适配代码。平台从配置目录自动发现它们，不维护第二份注册表。

## 合并前检查

1. 配置浏览与 Benchmark 当前 YAML 结构一致。
2. dry-run 和真实任务使用同一命令构造路径。
3. 页面不直接加载模型，也不安装模型依赖。
4. 结果页只消费公共输出结构，模型特有图仍由各模型 visual 模块生成。
5. 单个模型或数据集失效时，不影响平台读取其他项目。
